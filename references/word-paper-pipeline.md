# 论文生产线：Word / LaTeX 双轨

本文件只规定生产与验收纪律，不绑定某台电脑、某个 Word 样式文件或某个历史 CUMCM 模板。当届官方模板和规则始终优先。

## 1. 共同原则

无论使用 Word 还是 LaTeX，生产链都应满足：

内容源 -> 公式/表格/图 -> 引用 -> 候选 PDF -> 逐页目检 -> 提交版冻结。

关键要求：

- 数字、图、表可追溯到 Final Run；
- 公式可编辑且编号/引用稳定；
- 表题在上、图题在下等版式要求按当届规则执行；
- 不设置最低页数、最低字数、最低图数；
- 每次重大改稿后重新生成 PDF，不依赖旧中间文件。

## 2. Word 路线

推荐做法：

1. 先在官方 Word 模板或其副本中建立稳定样式；
2. 正文、标题、题注、表格、公式尽量使用样式而不是手工逐处调格式；
3. 公式使用 Word 原生公式或团队确认可稳定编辑的等价方案；
4. 表格优先三线表，但以当届官方要求为准；
5. 导出 PDF 后逐页检查，而不是只看 Word 编辑界面。

若使用 pandoc / python-docx / COM 等自动化，只把它们当生产工具。自动化生成后仍需检查：

- 公式是否丢失/错位；
- 表格是否超宽、断行异常；
- 中文字体是否替换；
- 题注和交叉引用是否正确；
- 页码、页眉页脚是否符合规则。

不要把某个机器上的固定路径、字体、MathType 版本或 Word COM 行为写成 coach 的通用前提。

## 3. LaTeX 路线

默认采用 `templates/competition-repo/paper/` 的分章节结构：

- `main.tex` 负责总装；
- `sections/` 负责正文；
- `reference/` 管理 BibTeX；
- `figures/` 与正文分离；
- `draft` 显示 TODO；
- `release` 隐藏 TODO。

当前骨架故意不绑定历史 `cumcmthesis.cls`。正式比赛时应根据当届官方规则替换 documentclass / 页面样式，而不是把旧年份模板当权威。

## 4. PDF 逐页目检

至少检查：

- 标题、摘要、正文层级；
- 字体、乱码、缺字；
- 公式完整、编号连续、引用正确；
- 表格不越界、不挤压、不出现异常断行；
- 图片清晰，单位、图例、坐标轴完整；
- 图表题注位置正确；
- 页码与分页正常；
- 参考文献和正文引用互相对应；
- 无 TODO、示例文字、旧版本结果、内部调试痕迹。

## 5. 发布纪律

`release` 只是“内容候选发布版”，不自动等于“符合当届格式的最终提交版”。

最终提交前必须再次完成：官方规则核对 -> 数字一致性核对 -> PDF 目检 -> 文件名/附件核对 -> 提交包冻结。

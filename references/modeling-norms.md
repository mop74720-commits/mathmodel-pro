# 建模通用规范

本文件是 coach 层的方法论底线。它不替代专项算法 Skill，也不把某个算法和某个题型机械绑定。

## 1. 子问题拆解

每个顶层问题至少明确六项：

1. 输入数据与题面已知条件；
2. 需要输出的结论或决策；
3. 变量、参数与单位；
4. 目标 / 评价指标；
5. 约束、边界与物理/业务限制；
6. 与其他问题的依赖关系以及需要的证据（表、图、指标、验证）。

题意存在歧义时，不直接凭经验选一种解释。至少保留候选解释，并用题目后续条件、数量级、边界行为或小规模验算排除不合理解释。

任何附件都应先实际检查，再决定模型。至少检查规模、字段、单位、缺失、异常、重复、范围和可派生变量；图像、网络等非表格数据也要先确认其真实结构。

## 2. 模型选择纪律

- 先识别问题结构，再讨论模型名称。
- 每问必须有可运行、可解释的 Baseline；复杂模型必须说明相对 Baseline 增加了什么价值。
- 候选模型通常控制在少量主线，不做模型堆砌。
- 模型复杂度由数据量、约束结构、可验证性和时间预算决定，而不是由“高级程度”决定。
- 任何经验型模型选择规则都只能作为候选生成器，不能作为自动决策树。
- 假设必须说明：为什么需要、影响哪些变量/结论、如果放松会发生什么。

## 3. Formulation — Implementation Contract

论文数学模型与代码实际实现必须同时维护，并明确二者差异。

至少记录：

- 目标函数 / 损失函数；
- 决策变量或状态变量；
- 参数及来源；
- 约束、边界和初值；
- 离散化 / 近似 / 截断；
- 求解器或算法；
- 停止条件；
- 随机性与 seed；
- 输出指标。

代码中的单位、坐标系、符号方向、边界和参数必须与模型合同一致。不得用“代码大致实现了公式”代替逐项核对。

## 4. 分题型最低纪律

### 优化

- 先证明/检查可行，再讨论最优。
- 明确 min/max、变量类型、上下界与全部约束。
- 求解器返回 success 后仍需回代关键约束，并记录 slack / violation。
- 整数变量不能先连续求解再无条件四舍五入；取整后必须重新验可行性。
- 启发式算法不得仅凭一次运行宣称全局最优；应通过多初值、多 seed、精确小实例、上下界或其他基准建立可信度。

### 预测

- 防止数据泄漏；时序问题默认按时间顺序划分。
- 预处理参数只在训练数据上拟合。
- 至少与简单 Baseline 比较，并报告合适的误差指标。
- 检查预测值的物理/业务边界和残差结构。

### 评价 / 排序

- 明确指标正负向、量纲处理、权重来源与归一化方式。
- 权重和评价方法必须与题意相符，不把方法默认输出误解释成百分制或概率。
- 必须检查权重扰动或替代方法下排序是否稳定。

### 机理 / 动力学 / 仿真

- 状态变量、参数、初值/边界条件和单位完整。
- 检查守恒量、单调性、极限行为或其他已知物理规律。
- 通过步长/网格收敛或方法互验说明数值误差不会改变主要结论；阈值根据问题精度需求确定，不使用固定百分比作为通用标准。

### 图论 / 网络

- 明确有向/无向、权重、容量、连通性和流量守恒。
- 算法前提必须满足，例如负权、容量、子回路等不能被默认忽略。

### 几何 / 空间问题

- 实体尺寸不能在没有论证时退化为点。
- 坐标系、角度单位、旋转方向、边界接触/碰撞定义必须统一。

## 5. 验证先于求解完成

验证方案应在最终结果出来前确定。候选包括：

- 约束回代与边界检查；
- 小规模精确解 / 枚举解对照；
- Baseline 对照；
- 独立算法或独立实现互验；
- 退化情形 / 极限情形；
- 守恒量、理论上下界；
- 交叉验证 / 留出验证；
- 参数敏感性与稳健性；
- 步长、网格、容差收敛；
- 多 seed / 多初值稳定性。

不要机械要求每题做全部验证；选择最可能推翻当前结论的验证。

## 6. Sensitivity / Robustness

敏感性分析不是固定的“±10%、±20%”仪式。扰动幅度应来自：

- 参数测量误差；
- 合理业务区间；
- 题目给定范围；
- 模型可能的结构不确定性。

报告的不只是目标值变化，还应关注方案是否改变、排序是否翻转、约束是否失效、结论是否跨过决策阈值。

## 7. Sanity Check

所有关键结果至少检查：

- 单位；
- 正负号；
- 数量级；
- 上下界；
- 极端输入；
- 物理/业务解释；
- 与简单估算是否相容。

## 8. 验收门禁

### FAIL：必须修复

- 题面要求遗漏；
- 模型与实现不一致；
- Final Run 与论文数字冲突；
- 关键约束未满足；
- 引用图表/数据不存在；
- 占位符或旧结果残留；
- 关键结论无法由代码、Run、图表或推导支持；
- 把 heuristic / limited search 写成已证明全局最优；
- 结果无法按记录的输入与参数复现。

### WARN：需要判断是否修复

- 图表后缺解释；
- 公式首次出现未定义；
- 模型优缺点空泛；
- 验证只做形式性展示；
- 章节过度重复；
- 参考文献与实际方法关系弱。

## 9. 唯一事实源

论文中的定量结果只能来自被冻结的 Final Run 或其明确派生结果。摘要最后定稿时，从正文和 Final Run 回填数字，不凭记忆重新输入。

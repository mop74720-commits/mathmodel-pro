# 获奖论文可复用写作模式

本文件只提炼结构性模式。获奖论文中的具体模型、章节编号、算法组合和篇幅不是通用模板。

## 1. 摘要

高质量摘要通常形成完整闭环：

问题 -> 核心方法 -> 关键求解策略 -> 定量结果 -> 验证/可信度 -> 实际含义。

值得保留的做法：

- 背景极短，迅速进入任务；
- 按问题组织，不让读者猜每段对应哪一问；
- 给关键数字，而不是只写“效果较好”；
- 策略类问题同时给目标值和核心决策变量；
- 有真正重要的验证结果时，在摘要中给出最能说明可信度的一项。

不应机械照搬：固定句式、固定关键词数量、固定“创新点三条”。

## 2. 问题分析

问题分析的价值是解释“为什么这样建模”，而不是重复题面。

较好的结构是：

已知什么 -> 真正困难是什么 -> 哪个结构可以利用 -> 准备怎样求解 -> 如何验证。

如果后续问题可以复用前问模型，应明确指出新增条件与复用关系。

## 3. 模型建立

优秀论文通常做到：

- 先定义变量和几何/业务关系，再给公式；
- 优化问题明确目标、变量和约束；
- 复杂模型在公式前先给直观解释；
- 利用对称性、等价变换、分层优化、降维等方式减少问题复杂度时，把这个推理过程写清楚；
- 模型名称服务于理解，不为了“创新感”强行起名。

## 4. 求解算法

真正有价值的是解释算法为何适合当前结构：

- 搜索空间如何缩小；
- 为什么需要精确法 / 数值法 / 启发式；
- 停止条件和精度如何确定；
- 是否存在可验证的小规模情形；
- 有没有独立方法互验。

算法流程图只在它比文字更能说明分支、循环、反馈或模块关系时使用。

## 5. 结果分析

不要停在“表 3 给出结果”。至少回答：

- 结果的关键数值是什么；
- 哪些变量真正主导结果；
- 为什么出现这种现象；
- 是否满足约束和常识；
- 对题目中的现实问题意味着什么。

将数学结果翻译成工程、经济或管理含义通常比再增加一个复杂模型更有价值。

## 6. 验证模式

获奖论文中最值得复用的通常不是某个算法，而是验证设计，例如：

- 模型退化到已知简单情形；
- 两条独立求解路线交叉印证；
- 理论边界 / 守恒量 / 几何性质检查；
- 精确小实例与近似算法对照；
- 参数扰动后主要结论保持；
- 后续问题的结果反向验证前文推理。

## 7. 图表

每张图先回答三个问题：

1. 它展示什么；
2. 为什么必须展示；
3. 它支持哪一句结论。

答不上第三问的图通常不应进入正文。

## 8. 模型评价

优点和局限必须具体到当前模型：精度、复杂度、数据要求、适用范围、可解释性、鲁棒性或计算成本。

“模型简单、效果好、推广性强”但没有证据，价值很低。

## 9. 使用获奖论文的边界

获奖论文可以作为写作与验证的观察样本，但不能作为当前赛题的事实源，也不能因为某篇获奖论文用了某方法就证明该方法适合当前题目。

# 论文阶段

> **定位：情景策略参考，不是执行阶段。** 仅在当前 Competition Repo 状态与本情景匹配时使用；不得因为文件编号或时间标签强制推进。


## 写作原则

- 论文随结果同步增长，但只写已经被证据支持的内容。
- 每个关键结论回答四件事：数值/现象是什么、为什么出现、是否可信、对题目意味着什么。
- 问题分析解释难点和路线，不大段重复题面。
- 图表按证据需求生成，不按数量生成；每张图都要说明它支持哪一句结论。
- 模型公式、代码实现、Final Run、图表和正文必须一致。
- 摘要早期保留草稿，最终数字在 Final Run 冻结后从正文回填。

## 分题型表达底线

- 优化：目标、变量、约束清晰；说明算法选择、可行性与最优性边界。
- 预测：数据划分、Baseline、误差指标、预测结果与不确定性/边界。
- 评价：指标方向、归一化、权重来源、得分/排序与稳定性。
- 机理/仿真：原理 -> 方程/关系 -> 数值求解 -> 结果 -> 物理/结构验证。

章节结构服务于当前题目，不强制每问固定四小节，也不强制最低页数、字数、图数或“创新点三条”。

## 图证写法

推荐最小闭环：

为什么看这张图 -> 图中观察到什么 -> 它支持/否定什么结论。

## 论文工程

默认使用 当前 Competition Repo 的 `paper/`（由独立 `competition-template` 初始化）：

- `main.tex` 只做总装；
- `sections/` 按问题与模型/求解/验证拆分；
- `draft` 显示 TODO，`release` 隐藏 TODO；
- `reference/`、`src/`、`figures/` 与正文分离；
- 发布候选不等于格式合规，最终仍按当届官方规则审计。

Word 队伍参见 `references/word-paper-pipeline.md`。

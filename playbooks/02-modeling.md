# 建模阶段

> **定位：情景策略参考，不是执行阶段。** 仅在当前 Competition Repo 状态与本情景匹配时使用；不得因为文件编号或时间标签强制推进。


## 必做

1. 明确输入、输出、变量、参数、单位、约束和问题间依赖。
2. 先按问题结构归类，再选择模型；不使用“题型 -> 唯一算法”的机械决策树。
3. 每问保留 Baseline + 至多 1–2 个有明确增益理由的主候选方案。
4. 假设逐条说明必要性、影响范围和放松后的可能变化。
5. 建立 Formulation — Implementation Contract：公式中的变量、参数、约束、近似、边界、停止条件与代码实现逐项对应。
6. 求解前定义验证方案：哪些证据可能推翻当前模型？
7. 写明模型选择理由：精度、可解释性、计算成本、数据要求、可验证性和时间预算。

## 不通过条件

- 模型只是“看起来高级”，没有相对 Baseline 的价值；
- 关键假设无法解释；
- 数学模型无法实际实现；
- 验证计划只能在得到结果后临时决定；
- 题意歧义仍被隐藏在公式中。

## 需要调用 Skill 的典型情景

- 模型族不确定 -> `MODEL_UNCERTAIN`
- 题意歧义 -> `PROBLEM_AMBIGUOUS`
- 假设过强 -> `ASSUMPTION_WEAK`
- 需要领域上下文 -> `DOMAIN_CONTEXT_NEEDED`

实际 Event→Skill 路径以当前 SkillHub `registry.yaml` 为准。

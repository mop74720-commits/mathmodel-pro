# 最后 6 小时

> **定位：情景策略参考，不是执行阶段。** 仅在当前 Competition Repo 状态与本情景匹配时使用；不得因为文件编号或时间标签强制推进。


## 先冻结，再评审

论文、代码和 Final Run 先形成一个冻结候选版本，再用评委视角重新检查。最后阶段不应一边大改一边自我验收。

## 禁止

- 更换核心模型；
- 大规模重写代码；
- 新增未经验证的复杂算法；
- 为了“创新”破坏已有稳定结果；
- 用新 Run 偷换已冻结结果而不更新证据链；
- 为页数、图数、模型数补无价值内容。

## 只做

- 题面要求是否全部回答；
- 摘要 / 正文 / Final Run 数字交叉核对；
- 模型合同与代码参数核对；
- 图表来源与正文 Claim 核对；
- 约束、边界、单位、数量级核对；
- 引用、格式、AI 使用声明核对；
- TODO、示例数据、旧结果、内部调试痕迹全文搜索；
- PDF 逐页目检；
- 提交文件名、附件和提交包冻结。

## 硬门禁

出现以下任一项不得提交：

- 关键问题漏答；
- 数字冲突；
- 关键约束违反；
- 引用图表不存在；
- 无法复现 Final Run；
- 占位符/旧结果残留；
- 强结论没有证据；
- 最终 PDF 明显排版/乱码错误。

# 交付安全与 Checkpoint Playbook

> **定位：跨时段的交付风险策略，不是新的比赛阶段。** 当存在明确截止时间、最终导出/打包链尚未验证、已有完整候选成果，或准备做可能破坏可提交性的高风险修改时使用。

## 目标

在不牺牲核心科学质量的前提下，始终保留一条可回退的提交路径。`Checkpoint` 只描述交付物准备度，不代表模型已经最优、结果已经 `COMPETITIVE_ENOUGH`，也不替代官方规则核验。

## 1. 先核验真实截止与提交约束

- 以目标竞赛当届官方来源核验截止日期、时区、提交入口、格式、文件数量/大小、命名、支撑材料和 AI 使用要求。
- 往届信息、仓库默认值和记忆只能作为检索线索，不能冒充当前届次规则。
- 无法核验的关键项保持 `UNKNOWN/CONFLICT`，不得给出 `SUBMISSION_READY`。
- Coach 根据剩余时间、导出耗时、网络/平台风险决定内部冻结与最迟安全导出时点；不使用跨竞赛固定小时数。

## 2. 尽早做一次端到端 Delivery Smoke

不要等论文写完才第一次测试交付链。只要已有最小真实结果，就应在成本合理时用真实/等价小样例走通：

`代码/Run → 结果表 → Figure → 论文源 → DOCX/PDF → 支撑材料 → 压缩包/提交目录 → 实际打开检查`

Smoke 的目标是尽早发现字体、公式、路径、模板、打包、文件大小、工具链或平台格式风险，不要求此时内容已经 Final。

记录成功/失败步骤、实际耗时与异常、运行环境、最小修复动作，以及下一次正式导出应预留的失败+重试成本。

## 3. Checkpoint V1：先拥有一个真实可提交候选

当首次出现“全部必需文件存在、可打开、满足已核验硬约束、关键结果与论文一致”的完整候选时，将其记为 `Checkpoint V1`。

- V1 必须是独立快照/副本/commit/tag 等可恢复对象，不得被后续优化原地覆盖。
- V1 可以不是最强科学版本；它的价值是提供确定的 rollback target。
- 只记录必要 manifest/关键哈希，不把 Checkpoint、hash、QA、provenance 等治理语言写进科学正文。
- 若当前 Competition Repo 模板没有固定 `releases/` 目录，不为满足本 Playbook 强行改目录；选择项目现有的可靠版本机制即可。

## 4. Checkpoint V2：在可回退前提下继续提升

V1 之后仍可继续建模、补验证、改图和优化论文，但在新分支/副本/新版本上修改，明确预期收益、失败模式与 rollback，重跑受影响的局部 QA/Final Run/Claim-Evidence；新版本完整可打开并通过必要检查后才晋升为 V2，V2 失败不得影响 V1。

不得把“已有 V1”解释为必须停止科学改进；是否继续由 Coach 根据 Impact / Uncertainty / Cost / Reversibility / Remaining time 决定。

## 5. 用“异常+恢复”而不是理论最快耗时做风险预算

对 LaTeX/DOCX 转换、复杂绘图、长计算、压缩、网络上传和第三方工具，不按一次成功的最快耗时排期。高风险修改前问：如果这次修改失败、运行超时或导出损坏，我是否仍能在安全时间内回到一个完整可提交版本？

若答案是否定的，且修改并非修复官方硬约束/P0 正确性问题，则默认降低范围或放弃该修改。

## 6. 内容冻结与最终导出

“冻结”由当前状态触发，不由固定时刻触发。常见信号是已有稳定 Final Run 与论文主线、剩余时间不足以承担结构性改动的失败+恢复成本、主要风险已转为格式/附件/引用/一致性/上传，或新改动的信息价值低于破坏可提交版本的风险。

冻结后只处理会影响正确性、证据一致性、官方合规或可打开性的确定问题。最终导出应从已确认的冻结源生成，不从临时工作副本拼装。

## 7. 最终包与人工提交确认

提交前确认最终 DOCX/PDF/附件可实际打开；文件名、格式、页数/大小、匿名要求符合已核验规则；压缩包可实际解压；Final Run、摘要关键数字、图表与正文一致；V1/V2 rollback 可恢复，并给人工登录、上传、平台校验和最终确认留出缓冲。

若 Agent 没有平台提交权限，必须明确把“上传并确认成功”留给用户；未经用户或平台证据，不得声称已经提交。

## 8. Rollback triggers

新导出出现系统性公式/字体/分页损坏、新 Run 改变正文关键数字但证据链来不及同步、新模型/代码导致完整结果链断裂、支撑材料或引用大范围不一致、或剩余安全时间不足以完成一次完整修复+复验时，优先回到最近通过的 Checkpoint，只合入必要且低风险的确定性修复。

## 9. 与 SkillHub 的边界

Coach 决定何时做 delivery smoke、保存/晋升 Checkpoint、冻结、接受风险和回退。`mathmodel-skills` 只处理局部能力，例如 `PRE_SUBMISSION`、`FIGURE_RENDER_NEEDED`、`FINAL_RESULT_NEEDS_REVIEW` 以及 DOCX/LaTeX/PDF Tool。不得为了实现本 Playbook 在 SkillHub 新建全局“竞赛阶段”或强制门禁。
